# バイク向けランダム目的地Webアプリ 要件定義

> 初期検討段階の要件定義です。実装を進める中で変更され得ます。

## 1. 目的

現在地周辺から、バイクで走りに行くための目的地をランダムに提示するWebアプリとする。

## 2. 運用環境

- Webアプリ
- Cloudflare上で運用する
- 主なリソース
  - Cloudflare Workers
  - Workers Static Assets
- Workers KVは前提として導入する（Overpass APIのレート制限を吸収するためのキャッシュ用途、無料枠内で運用）
- D1は必要になった場合のみ追加を検討する
- 地図・道路データはOpenStreetMap系を利用する想定とする

## 3. 基本条件

- 現在地を基準に目的地を検索する
- 探索範囲を指定できること
  - 例：半径50km
- 道路で到達可能な地点を候補とする
- 直線路途中の単なる道端は除外する
- 少なくとも交差点など、地点として区別できる場所を候補とする
- 行き止まりは除外する

## 4. 目的地種別

以下から選択できること。

- 店
- 店以外

### 4.1 店

店を選択した場合、以下から選択できること。

- 食事・休憩
- 買い物・その他

### 4.2 店以外

店舗以外の地点を目的地候補とする。

目的地付近に停車できる場所が必要かどうかを選択できること。

- 停車できる場所が必要
- 停車場所の有無を問わない

停車可否については、地図データ等から判断可能な場合のみ条件として使用する。

## 5. 高速道路・高規格道路の除外

- 高速道路・高規格道路は常時除外する
- 高速道路・高規格道路から100m以内にある目的地候補も除外する

## 6. 地図表示・ナビ連携

- 抽選した目的地を地図上に表示する
- 地図を見て、利用者が目的地として適切か大まかに判断できること
- 採用しない場合は別の目的地を再抽選できること
- 採用する場合、ナビアプリで目的地として指定できる情報をコピーできること
  - 基本は緯度・経度を想定する
  - 店の場合は、取得可能でナビ指定に利用できるなら名称・住所も表示する
- ナビアプリへの直接連携は必須としない
- コピーした情報を利用者がナビへ設定できればよい

## 7. 周辺情報表示

- 地図上の目的地について、1回の操作で周辺情報一覧を表示できること
- 一覧には少なくとも以下を含める
  - 目的地点そのものの情報
  - 目的地点周辺のPOI
- 周辺POIは、地図データから取得可能な範囲で表示する
- 一覧から各POIの位置を地図上で確認できること
- 周辺情報表示のために別画面へ遷移する必要はなく、地図確認の流れの中で利用できること

## 8. 画面構成（ラフ案）

想定端末はiPhone Chromeを主とするモバイルWeb。

画面イメージは `docs/mockups/` 以下のPNGを参照。

主要導線:

1. 条件設定（現在地・探索範囲・目的地種別とその条件を設定）
2. 探索結果を地図で確認（採用／別の場所へ再抽選／ナビ用情報コピーをその場で選べる）
3. 周辺情報（ボトムシートを引き上げて、画面遷移なしで目的地本体と周辺POIの一覧を表示）
4. ナビ用情報コピー（緯度経度・名称・住所を個別／一括コピー）

## 9. 未確定事項・今後詰める点

- フロントエンドのビルド有無（バンドラーなしの素のHTML/CSS/JSか、Vite導入か）
- Workers側でルーティング用のライブラリ（Honoなど）を使うか、素の実装で進めるか
- 地図表示ライブラリの選定（Leaflet / MapLibre GL JS など。無料枠内で収まることを選定基準にする）
- OSMデータの取得方法（Overpass APIを直接叩くか、別の手段を検討するか。同上、無料枠内で収まることを選定基準にする）
- D1導入の要否・タイミング（KVは導入確定。詳細は docs/decisions/260828-infra-cloudflare-kv.md 参照）
- プロジェクト名の最終確定（現在の仮称: `touring-gacha`）
