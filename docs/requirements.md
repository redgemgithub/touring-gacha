# バイク向けランダム目的地Webアプリ 要件定義

> 初期検討段階の要件定義です。実装を進める中で変更され得ます。

## 1. 目的

現在地周辺から、バイクで走りに行くための目的地をランダムに提示するWebアプリとする。

## 2. 運用環境

- Webアプリ
- Cloudflare上で運用する
- 主なリソース
  - Cloudflare Workers
  - Workers Static Assets
- Workers KVは前提として導入する（Overpass APIのレート制限を吸収するためのキャッシュ用途、無料枠内で運用）
- D1は必要になった場合のみ追加を検討する
- 地図・道路データはOpenStreetMap系を利用する想定とする

## 3. 基本条件

- 現在地を基準に目的地を検索する
- 探索範囲を指定できること
  - 例：50km
  - 指定距離に近い帯にある地点を候補とする。選択肢どうしの間に中抜けができないよう、隣り合う選択肢との中間値を境界にする（両端の選択肢だけ、指定距離の10%と固定5kmの大きい方をマージンとする）。例: 10/30/50/100kmの選択肢なら、帯は5〜20km／20〜40km／40〜75km／75〜110km
  - 帯の範囲内に候補がなければ、範囲を自動的に広げず、見つからなかった旨を伝える
  - 距離は直線距離とする
- 道路で到達可能な地点を候補とする
- 直線路途中の単なる道端は除外する
- 少なくとも交差点など、地点として区別できる場所を候補とする（「交差点」の目的地種別として実現。詳細は4.3参照）
- 行き止まりは除外する

## 4. 目的地種別

以下から選択できること。

- スポット（店）
- スポット（店以外）
- 交差点

「店以外」の次に構造の異なる「交差点」が並ぶ違和感を避けるため、共通の括りとして「スポット」という表記を用いる（詳細: docs/decisions/260830-phase4b交差点検出実装.md）。

### 4.1 スポット（店）

店を選択した場合、以下から選択できること。

- 食事・休憩
- 買い物・その他

### 4.2 スポット（店以外）

店舗以外の地点（峠・展望・山頂等）を目的地候補とする。

目的地付近に停車できる場所が必要かどうかを選択できること。

- 停車できる場所が必要
- 停車場所の有無を問わない

停車可否については、地図データ等から判断可能な場合のみ条件として使用する。「停車できる場所が必要」を選んだ場合、候補付近（1km以内）に駐車場データが見つからない候補は除外する（判断できないものを通すのではなく、確実に確認できたものだけ残す。詳細: docs/decisions/260829-phase4a-店以外タグ地点と停車場所.md）。

### 4.3 交差点

道路網の構造（複数の道が交わる地点）から、タグの有無に関わらず交差点を目的地候補とする。詳細条件（停車できる場所、等）は設けない。

現在地から乱数の方角×指定距離ちょうどの1点（仮地点）の周辺のみを検索する性質上、候補は帯全体ではなく仮地点周辺（最大1km程度）に局所的に集まる。この点は「スポット（店以外）」とは異なる挙動であることを、目的地種別を分けることで利用者に明示している（詳細: docs/decisions/260830-phase4b交差点検出実装.md）。

## 5. 高速道路・高規格道路の除外

- 高速道路・高規格道路は常時除外する
- 高速道路・高規格道路から100m以内にある目的地候補も除外する

## 6. 地図表示・ナビ連携

- 抽選した目的地を地図上に表示する
- 地図を見て、利用者が目的地として適切か大まかに判断できること
- 採用しない場合は別の目的地を再抽選できること
- 採用する場合、ナビアプリで目的地として指定できる情報をコピーできること
  - コピーする項目（緯度経度／名称／住所）は、コピーの都度ではなくアプリ全体で1回設定する（利用者が使うナビアプリはほぼ固定されているため）
  - 目的地・周辺POIとも、対象の行/ボタンを1秒間長押しすると、アプリ全体のコピー設定を無視して緯度経度のみを強制的にコピーできる（チェーン店名など、名称だけではナビアプリの検索で目的の地点に絞り込めない場合の逃げ道。通常のタップ挙動は変わらない）
- ナビアプリへの直接連携は必須としない
- コピーした情報を利用者がナビへ設定できればよい

## 7. 周辺情報表示

- 地図上の目的地について、1回の操作で周辺情報一覧を表示できること
- 一覧には少なくとも以下を含める
  - 目的地点そのものの情報
  - 目的地点周辺のPOI
- 周辺POIは、地図データから取得可能な範囲で表示する
- 一覧から各POIの位置を地図上で確認できること
- 周辺情報表示のために別画面へ遷移する必要はなく、地図確認の流れの中で利用できること
- 一覧の各POIも、目的地と同様にナビアプリ用の情報をコピーできること
- 一覧の各POIも、目的地と同様に1秒長押しで緯度経度を強制コピーできること（詳細は6.参照）

## 8. 画面構成（ラフ案）

想定端末はiPhone Chromeを主とするモバイルWeb。

画面イメージは `docs/mockups/` 以下のPNGを参照。

主要導線:

1. 条件設定（現在地・探索範囲・目的地種別とその条件を設定。ナビ用にコピーする項目もここで1回設定する）
2. 探索結果を地図で確認（目的地情報をタップしてナビ用情報をコピー／再抽選／周辺情報を表示）
3. 周辺情報（ボトムシートを引き上げて、画面遷移なしで目的地本体と周辺POIの一覧を表示）
4. ナビ用情報コピー（目的地・周辺POIとも、対象の行をタップでコピー、長押しで緯度経度を強制コピー）

## 9. 未確定事項・今後詰める点

- OSMデータの取得方法（Overpass APIを直接叩くか、別の手段を検討するか。無料枠内で収まることを選定基準にする）
- D1導入の要否・タイミング（KVは導入確定。詳細は docs/decisions/260828-infra-cloudflare-kv.md 参照）
- プロジェクト名の最終確定（現在の仮称: `touring-gacha`）

決定済み（詳細は docs/decisions/260828-infra-cloudflare-kv.md 参照）:
- フロントエンドのビルド有無 → バンドラーなし
- Workers側のルーティングライブラリ → Hono採用
- 地図表示ライブラリ → MapLibre GL JS、タイル提供元 → MapTiler無料プラン
