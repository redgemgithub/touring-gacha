# コピー方式の仕様変更: 都度選択のモーダルから、アプリ共通の設定へ

## 背景

Phase 3の実機確認で、周辺情報展開画面のPOIを選択（地図フォーカス）できても、その情報をコピーできずナビアプリでの検索に使えないという問題が見つかった。対応を検討する過程で、既存の「目的地のコピー」の仕組み自体にも見直すべき点があることが分かった。

## 検討の経緯（採用しなかった案）

- **周辺POIごとにコピーモーダルを開く案**: 既存のコピーモーダル（緯度経度・名称・住所を個別/一括コピー）をPOIにも流用する案。実装は容易だが、展開済みのシートの上にさらにモーダルが重なり、画面遷移的な煩雑さが増す懸念があった
- **コピーの都度、対象項目をラジオボタン/チェックボックスで選ぶ案**: コピー操作のたびに「何をコピーするか」を選ばせる案。しかし、利用者が使うナビアプリは通常固定されており（Google Mapsのように何を貼り付けても検索できるものもあれば、名称のみ・緯度経度のみでなければ検索できないものもある）、**都度選ばせること自体が余計な手間**になると判断した

## 決定

- コピーする項目（緯度経度／名称／住所）の選択は、**コピーの都度ではなくアプリ全体で1回設定する**ものとし、ブラウザのlocalStorageに保存する
- 既存のコピーモーダルの役割を、「今すぐコピーするボタン集」から「次回以降のコピーに何を含めるかを選ぶ、チェックボックス付きの設定画面」に変更する。設定の入り口は条件設定画面の上部に置く
- 実際のコピー操作はモーダルを介さず直接行う
  - 目的地: 既存の「ナビ用情報」ボタンをタップした瞬間に、設定に従った内容を直接コピーする（モーダルは開かない）
  - 周辺POI: 一覧の行をタップすると選択（地図フォーカス、既存動作のまま）、**選択中の行をもう一度タップするとコピー**する
  - どちらも「コピーしました」という短い表示（トースト）を出す
- 「選択」と「コピー」を1回のタップに分けず2回に分けている理由: 周辺POI一覧は行をタップするたびに地図フォーカスが動く（プレビュー的な操作）。もし1回のタップで即コピーまで行うと、確認のたびに「コピーしました」表示が毎回出てしまい煩わしい。選択（プレビュー）とコピー（確定操作）を分けることで、これを避ける

## この決定に伴う既存仕様への影響

- docs/requirements.md 6.（ナビ連携）: 「ナビアプリで指定できる情報をコピーできること」という要件自体は変わらないが、コピー対象項目の選び方が「都度」から「アプリ共通の設定」に変わる
- docs/requirements.md 7.（周辺情報表示）: 「一覧から各POIの位置を地図上で確認できること」に加え、周辺POIの情報もコピーできるようにする（要件には明記されていなかった拡張）
- 目的地の「ナビ用情報」ボタンの挙動が変わる（モーダルを開かなくなり、即座にコピーされる）

## 今回のスコープ外

- コピー項目設定画面自体（歯車アイコン等の本格的な設定画面）は作らず、条件設定画面に小さなリンク/ボタンを置くのみとする。本格的な設定画面が必要になった場合はPhase 5（仕上げ・残課題）以降で検討する
