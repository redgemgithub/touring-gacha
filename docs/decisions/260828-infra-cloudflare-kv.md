# インフラ構成方針: Cloudflare Workers + KV（無料枠運用）

## 決定事項

- touring-gachaはCloudflare Workers + Workers Static Assets + Workers KV（すべて無料枠）で運用する
- Workers KVは「必要になったら検討する」対象から外し、最初から導入前提とする
  - 理由: 目的地探索のたびにOverpass API（公開サーバー、レート制限あり）を叩く設計だと、Workers単体（ステートレス）ではレート制限を吸収できない。探索結果をKVにキャッシュすることを前提に設計する
- D1導入の要否は引き続き未確定（必要になった場合のみ検討）

## 無料枠運用の考え方

- 「無料」は未来永劫である必要はない。自分ひとりが使う規模で維持できれば十分
- 無料枠を超えた場合は自動課金に移行するのではなく、サービスが利用不可になる（止まる）方が望ましい。意図しない課金の発生を避けるため
- 地図タイル・POIデータの提供元、OSMデータ取得方法などの未確定事項も、この「無料枠内で収まること」を選定基準とする

## 参考: Workers KV 無料プランの制限（2026-08-28確認時点）

- 読み取り: 100,000回/日
- 書き込み: 1,000回/日
- 削除: 1,000回/日
- リスト操作: 1,000回/日
- ストレージ容量: 1GB
- すべてUTC 0時にリセット
- 出典: https://developers.cloudflare.com/kv/platform/pricing/（料金体系は変わりうるため、実装時に最新値を再確認すること）

個人利用規模であれば、書き込み1,000回/日でも十分まかなえるとの判断からこの方針を確定した。

## Overpass APIの利用制限（2026-08-28確認時点）

公開インスタンス `overpass-api.de`（`gall.openstreetmap.de` / `lambert.openstreetmap.de` の2台構成）を利用する前提での確認結果。

- **目安の利用量**: 1日10,000クエリ・1GBデータ未満なら他の利用者に迷惑をかけないと言える範囲。定期的・自動的な利用（Webアプリのバックエンドから等）の場合は、この数値を100で割った水準（**1日100クエリ・10MB未満**）を目安にすべきとされている
- **識別**: リクエストにUser-AgentまたはRefererヘッダーで、送信元を識別可能にすることが必須
- **並列禁止**: 同一クライアントから複数クエリを同時実行してはならない。1つずつ順番に送る
- **キュー**: スロットが空くまで最大15秒キューで待機。それでも空かない場合はHTTP 429で拒否される
- **タイムアウト**: デフォルト180秒（`[timeout:...]`で最大900秒まで延長可能）
- **メモリ上限**: デフォルト512MiB（`[maxsize:...]`で調整可能、上限あり）
- **エラー時の挙動**: 429やタイムアウト系エラーを受けたら、即リトライせず30秒程度待ってから再試行する
- **代替インスタンス**: 過負荷時のフォールバック先として、Private.coffee運営の無制限インスタンス等、他の公開インスタンスも存在する
- 出典: [Overpass API - OpenStreetMap Wiki](https://wiki.openstreetmap.org/wiki/Overpass_API)（数値は変わりうるため、実装時に再確認すること）

### 設計への反映

- 個人ひとりが使う規模であれば、目安の「1日100クエリ・10MB」の範囲には収まる想定だが、目的地の再抽選（同じ地域を何度も検索するケース）でクエリ数が膨らみやすいため、KVキャッシュ導入の判断（上記「決定事項」）は妥当と言える
- Workers側からのリクエストには、touring-gachaを識別できるUser-Agent（例: `touring-gacha/0.1 (personal use)`）を付与する
- 429・タイムアウト発生時は、指数バックオフ等ですぐに再試行しない実装にする
- 複数のOverpassインスタンスへ同時に投げる（並列化して速くする）設計は、fair use policyの「並列禁止」に抵触するため行わない

## フロントエンド/Workers側の技術選定

プロジェクト雛形作成に先立ち、以下2点を決定した。

### フロントエンドのビルドツール有無 → バンドラーなし（素のHTML/CSS/JS）

- README記載の当初案どおり、1枚のindex.htmlを画面状態の切り替えで構成する程度の規模
- Vite等導入のメリット（モジュール分割・HMR）より、ビルドステップを持たないことによる維持コストの低さを優先する
- 地図ライブラリ（MapLibre GL JS / Leaflet等）もUMD版をCDNのscriptタグで読み込めるため、npm importは必須にならない

### Workers側のルーティング/フレームワーク → Hono採用

- [Hono](https://github.com/honojs/hono)はCloudflare Workers等のエッジランタイム向けに設計された薄いWebフレームワーク（バックエンド側。フロントエンドとは無関係）
- 圧縮後約14KBと軽量で、追加のビルドステップは不要（wranglerが元々TypeScriptをバンドルするため）
- JSONリクエストのパースやエラーハンドリングなど、素実装だと定型化しがちなコードを減らせる
- 採用理由の裏付け（2026-08-28時点でWeb検索により確認）:
  - GitHub約32,000スター、MITライセンス、2,800以上のコミットで開発継続中
  - npm週間ダウンロード数は2022年の1,000/週から2026年時点で数百万〜2,000万/週規模まで急成長（出典により幅あり）
  - Cloudflare自身（D1、Workers KV関連）、Deno、Clerk、Unkey等が本番採用
  - Cloudflare公式ドキュメントにも掲載されており（[Cloudflare Workers docs: Hono](https://developers.cloudflare.com/workers/framework-guides/web-apps/more-web-frameworks/hono/)）、Workers上での定番選択と言える状態
- 「軽い」の定義（機能少・画面シンプル・無料維持）には抵触しない小さな依存追加と判断

## 地図ライブラリ・タイル提供元の選定

「無料枠を超えたら自動課金でなく利用不可になる」という運用方針の基準で、以下の候補を比較検討した（2026-08-28、Web検索により確認）。

| 候補 | 無料枠超過時の挙動 | セットアップ手間 | 備考 |
|---|---|---|---|
| 生のOSMタイル（tile.openstreetmap.org） | 数値上限が非公開で「重い」と判断されると予告なくブロック。挙動が不透明 | ゼロ（アカウント不要） | [利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)上、そもそもサードパーティアプリでの本格利用は非推奨 |
| **MapTiler無料プラン** | **月10万マップロードで停止、翌月まで自動復帰。自動課金なし**と公式に明記（[出典](https://www.maptiler.com/news/2019/11/manage-your-costs-with-maptiler-cloud/)） | 低（サインアップ+APIキー） | MapLibre GL JSの開発元でもあり相性がよい |
| Stadia Maps無料プラン | クレジット制で個人利用は許可されているが、超過時の具体的挙動が資料上不明瞭（[Service Limits](https://docs.stadiamaps.com/limits/)） | 低〜中 | 判断材料不足のため保留 |
| Protomaps（PMTiles）+ Cloudflare R2 | R2は転送量が常に無料（構造上、無料枠うんぬんの話ではない）。ストレージ超過分のみ課金対象になりうる | 高（タイルデータの生成・R2ホスティング・pmtilesプラグイン組み込みが必要） | 既存のCloudflare方針と最も一貫するが、初期構築の手間が大きい |

### 決定

- **地図ライブラリ: MapLibre GL JS**
  - MapTilerとの相性がよい（MapTilerがMapLibre GL JSの開発元）
  - 将来Protomapsへ移行する場合もライブラリを変えずに済む（LeafletはPMTilesベクトルタイルとの相性がMapLibreほど良くない）
- **タイル提供元: MapTiler無料プラン**
  - 「無料枠超過→自動課金でなく利用不可」という基準に公式ドキュメントで明確に合致する数少ない候補
  - セットアップの手間も小さい（サインアップ+APIキー取得のみ）
- **見送った候補・将来の代替案**: Protomaps + Cloudflare R2
  - 思想的には最もCloudflare方針と一貫する（転送量が構造的に無料）が、タイルデータ生成というもう一段重い作業が要るため、今回は見送る
  - 将来、MapTiler無料枠の制約が問題になった場合の移行先候補として記録しておく
