# インフラ構成方針: Cloudflare Workers + KV（無料枠運用）

## 決定事項

- touring-gachaはCloudflare Workers + Workers Static Assets + Workers KV（すべて無料枠）で運用する
- Workers KVは「必要になったら検討する」対象から外し、最初から導入前提とする
  - 理由: 目的地探索のたびにOverpass API（公開サーバー、レート制限あり）を叩く設計だと、Workers単体（ステートレス）ではレート制限を吸収できない。探索結果をKVにキャッシュすることを前提に設計する
- D1導入の要否は引き続き未確定（必要になった場合のみ検討）

## 無料枠運用の考え方

- 「無料」は未来永劫である必要はない。自分ひとりが使う規模で維持できれば十分
- 無料枠を超えた場合は自動課金に移行するのではなく、サービスが利用不可になる（止まる）方が望ましい。意図しない課金の発生を避けるため
- 地図タイル・POIデータの提供元、OSMデータ取得方法などの未確定事項も、この「無料枠内で収まること」を選定基準とする

## 参考: Workers KV 無料プランの制限（2026-08-28確認時点）

- 読み取り: 100,000回/日
- 書き込み: 1,000回/日
- 削除: 1,000回/日
- リスト操作: 1,000回/日
- ストレージ容量: 1GB
- すべてUTC 0時にリセット
- 出典: https://developers.cloudflare.com/kv/platform/pricing/（料金体系は変わりうるため、実装時に最新値を再確認すること）

個人利用規模であれば、書き込み1,000回/日でも十分まかなえるとの判断からこの方針を確定した。

## フロントエンド/Workers側の技術選定

プロジェクト雛形作成に先立ち、以下2点を決定した。

### フロントエンドのビルドツール有無 → バンドラーなし（素のHTML/CSS/JS）

- README記載の当初案どおり、1枚のindex.htmlを画面状態の切り替えで構成する程度の規模
- Vite等導入のメリット（モジュール分割・HMR）より、ビルドステップを持たないことによる維持コストの低さを優先する
- 地図ライブラリ（MapLibre GL JS / Leaflet等）もUMD版をCDNのscriptタグで読み込めるため、npm importは必須にならない

### Workers側のルーティング/フレームワーク → Hono採用

- [Hono](https://github.com/honojs/hono)はCloudflare Workers等のエッジランタイム向けに設計された薄いWebフレームワーク（バックエンド側。フロントエンドとは無関係）
- 圧縮後約14KBと軽量で、追加のビルドステップは不要（wranglerが元々TypeScriptをバンドルするため）
- JSONリクエストのパースやエラーハンドリングなど、素実装だと定型化しがちなコードを減らせる
- 採用理由の裏付け（2026-08-28時点でWeb検索により確認）:
  - GitHub約32,000スター、MITライセンス、2,800以上のコミットで開発継続中
  - npm週間ダウンロード数は2022年の1,000/週から2026年時点で数百万〜2,000万/週規模まで急成長（出典により幅あり）
  - Cloudflare自身（D1、Workers KV関連）、Deno、Clerk、Unkey等が本番採用
  - Cloudflare公式ドキュメントにも掲載されており（[Cloudflare Workers docs: Hono](https://developers.cloudflare.com/workers/framework-guides/web-apps/more-web-frameworks/hono/)）、Workers上での定番選択と言える状態
- 「軽い」の定義（機能少・画面シンプル・無料維持）には抵触しない小さな依存追加と判断
