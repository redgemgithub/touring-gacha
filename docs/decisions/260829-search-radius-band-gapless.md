# 探索範囲の帯の中抜け解消

## 経緯

docs/decisions/260829-search-radius-band.md で導入した帯検索（指定距離±マージン、マージン=max(指定距離×10%, 5km)）を実際にデプロイして操作したところ、選択肢どうしの間に検索できない「中抜け」があることに気づいた。

- 10km→[5,15]、30km→[25,35]、50km→[45,55]、100km→[90,110]
- 15〜25km、35〜45km、55〜90kmは、どの選択肢を選んでも検索できない

再抽選機能がある以上、意図的に中抜けを残すのは利用者への押し付けになる（「その範囲は次回のお楽しみ」を強制することになる）と判断し、解消することにした。

## 決定: 隣り合う選択肢どうしの境界を中間値にする

```
帯の内側境界 = 一つ手前の選択肢との中間値（最小の選択肢だけ、指定距離−マージン）
帯の外側境界 = 一つ後の選択肢との中間値（最大の選択肢だけ、指定距離＋マージン）
```

| 指定距離 | 旧（中抜けあり） | 新（中抜けなし） |
|---|---|---|
| 10km | 5〜15km | 5〜20km |
| 30km | 25〜35km | 20〜40km |
| 50km | 45〜55km | 40〜75km |
| 100km | 90〜110km | 75〜110km |

両端（最小の10km・最大の100km）だけは、これまで通りのマージン計算式（指定距離の10%と固定5kmの大きい方）を使う。中間の選択肢（30km・50km）は、隣接する選択肢との中間値を境界にすることで、選択肢全体で5〜110kmを隙間なくカバーする。

## 実装

`src/lib/geo.ts`と`public/js/geo.js`の`computeDistanceBand`に、UIの探索範囲チップの値（`RADIUS_STEPS = [10, 30, 50, 100]`）を持たせ、指定距離のインデックスに応じて隣接値との中間値を計算するよう変更した。未知の値（`RADIUS_STEPS`にない値）が渡された場合は、両端と同じ対称マージンにフォールバックする。

候補の絞り込みロジックが変わるため、docs/decisions/260829-cache-key-versioning.md の原則に従い、KVキャッシュキーのバージョンを`ov:v2`→`ov:v3`に上げ、本番に残っていた`ov:v2:...`エントリも削除した。
