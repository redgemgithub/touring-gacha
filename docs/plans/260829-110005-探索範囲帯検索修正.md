# 探索範囲を「以内」から「帯」に修正

## Context

Phase 2完了後の実機確認で、探索範囲の仕様が「指定距離以内」（円内）として要件定義・モックアップ・実装のすべてで一貫していたことが判明したが、これはアプリの目的（指定距離を走るための目的地を探す）に照らすと仕様漏れだった。修正方針は決定済み（[docs/decisions/260829-search-radius-band.md](../decisions/260829-search-radius-band.md)）。Phase 3着手前に、この修正をPhase 1・2の実装に反映する。

## DoD（完了条件）

1. 探索範囲Xkmを指定して検索すると、候補が現在地から「X±マージン」（マージン = max(X×10%, 5km)）の範囲内に絞り込まれる
2. 帯の範囲内に候補が1件もない場合、範囲を自動的に広げず、既存の「条件に合う目的地が見つかりませんでした」表示になる
3. 結果画面の「探索範囲」表示が、実際の帯（例: 「45〜55km」）を反映した表記になる
4. 高速道路100m除外・KVキャッシュ・再抽選の既存動作は変更後も同様に機能する
5. `npm run typecheck`が通る
6. ローカル・実ブラウザで一連の流れを確認できる

## 技術設計

### `src/lib/geo.ts`（拡張）

```ts
export const RADIUS_BAND_TOLERANCE = 0.1;
export const RADIUS_BAND_MIN_MARGIN_KM = 5;

export function computeDistanceBand(radiusKm: number): { innerKm: number; outerKm: number; marginKm: number } {
  const marginKm = Math.max(radiusKm * RADIUS_BAND_TOLERANCE, RADIUS_BAND_MIN_MARGIN_KM);
  return { innerKm: radiusKm - marginKm, outerKm: radiusKm + marginKm, marginKm };
}
```

### `src/lib/overpass.ts`（修正）

`buildOverpassQuery`内で、候補検索・高速道路検索の両方の半径を`radiusKm`ではなく`computeDistanceBand(radiusKm).outerKm`から計算する（帯の外側境界までを検索し、内側境界での絞り込みは`/process`側で行う）。

### `src/types.ts`（修正）

`ProcessRequestBody`に`lat: number`, `lon: number`, `radiusKm: number`を追加する（帯フィルタの計算に現在地座標と指定距離が必要なため）。

### `src/routes/destinations.ts`（修正）

`/process`ハンドラで、`excludeNearHighways`適用後・`putCachedCandidates`前に、帯フィルタを追加する。

```ts
const { innerKm, outerKm } = computeDistanceBand(radiusKm);
candidates = candidates.filter((cand) => {
  const distKm = haversineDistanceKm(lat, lon, cand.lat, cand.lon);
  return distKm >= innerKm && distKm <= outerKm;
});
```

`isValidProcessRequest`に`lat`/`lon`/`radiusKm`の検証を追加する。

### フロントエンド

- `public/js/geo.js`: サーバー側`computeDistanceBand`と同等の関数を追加（バンドラーなし構成のため、既存のhaversine/bearingと同様にサーバー側とは別実装になる）
- `public/js/search.js`: `processSearch`呼び出し時のリクエストボディに`lat`, `lon`, `radiusKm`を追加
- `public/js/views/result.js`: `radiusLabel.textContent`を、`探索範囲 ${radiusKm}km 圏内`から、帯の実際の範囲を示す表記（例: `探索範囲 ${innerKm}〜${outerKm}km`）に変更

### ドキュメント更新

- `docs/requirements.md` 3.基本条件: 探索範囲の記述を帯検索・自動拡大しない旨に修正
- `CLAUDE.md` 守るべきドメインルール: 同様の内容を簡潔に追記
- `README.md`: ユーザーからREADME記載相当の重要度と指摘されたため、簡潔な注記と決定記録へのリンクを追加
- `docs/feature-map.md`: 該当行があれば更新

## 実装ステップ順序

1. `src/lib/geo.ts`に`computeDistanceBand`追加 → typecheck
2. `src/lib/overpass.ts`修正（`buildOverpassQuery`が帯の外側境界を使うよう変更） → typecheck
3. `src/types.ts`修正（`ProcessRequestBody`拡張） → typecheck
4. `src/routes/destinations.ts`修正（帯フィルタ追加、バリデーション拡張） → typecheck
5. `wrangler dev` + curlで、`/prepare`→（ダミーまたは実際の）Overpass応答→`/process`の一連を実行し、帯の範囲外候補が結果から除外されていることを確認
6. `public/js/geo.js`, `search.js`, `views/result.js`を修正
7. 実ブラウザ（Playwright）でE2E確認: 検索結果の候補距離が帯の範囲内であること、結果画面の表示が新しい帯表記になっていること

## リスク・注意点

- 帯フィルタの追加により、同じ検索条件でも候補数が減る（場合によってはゼロになる）。これは意図した仕様であり、バグ修正の対象ではない
- 検証時のOverpassへの実リクエストは、外部APIレート制限budgeting方針（メモリ記録: external-api-rate-limit-budgeting）に従い、必要最小限に留める
- Phase 3の周辺POI検索（固定500m円内）には影響しない
