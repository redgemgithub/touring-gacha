# 長押しで緯度経度を強制コピーする機能の追加

## Context

本番運用中、周辺POIの名称が「ENEOS」のようなチェーン店名だった場合、コピーした情報をナビアプリに貼り付けて検索しても、直前に選んだ地点とは限らない別店舗がヒットしてしまう問題が見つかった。

かといって、常に地名（住所）を付け足す設定にするのが正解とも限らない（利用者が使うナビアプリによっては住所を混ぜるとかえって検索精度が落ちる場合がある、というのがコピー項目をアプリ全体で1回設定にした元々の理由）。そこで、通常のコピー挙動（アプリ全体のコピー項目設定に従う）はそのままに、**利用者が「これはチェーン名だけでは特定できない」と一目で判断した場合に、その場で緯度経度だけを強制的にコピーできる裏技**を追加する。

## 決定事項（ユーザー確認済み）

- **適用範囲**: 目的地・周辺POIの区別なく、コピーに関わる全箇所に適用する
  - 下部シート折りたたみ時の「⧉ ナビ用情報」ボタン（目的地）
  - 展開時の一覧内の目的地行（`#nearby-destination-item`）
  - 展開時の一覧内の周辺POI各行
  - 理由: 目的地自体も店舗チェーン名（例: セブンイレブン）になりうるため、同じ曖昧さの問題が起こりうる
- **操作方法**: 1秒間の長押しで、アプリ全体のコピー項目設定を無視して緯度経度のみを強制的にコピーする。通常のタップ挙動（目的地ボタンは即コピー、一覧の行は「選択→再タップでコピー」）は変更しない
- **フィードバック表示**: 通常のコピーと区別できるよう、長押しコピー時は「緯度経度をコピーしました」という専用のトースト文言にする（通常は「コピーしました」のまま）

## 技術設計

### 新規: `public/js/long-press.js`

Pointer Events（`pointerdown`/`pointermove`/`pointerup`/`pointercancel`）ベースの長押し検出ユーティリティを新規作成する。既存の`click`リスナー（タップ時の選択・即コピー挙動）はそのまま残し、長押し発火時だけそのあとに続く`click`イベントを捕捉フェーズでキャンセルする方式にする。これにより、既存のタップ処理コードを書き換えずに長押しを追加できる。

```js
export function attachLongPress(el, { onLongPress, thresholdMs = 1000, moveTolerancePx = 10 } = {}) {
  let timer = null;
  let startX = 0;
  let startY = 0;
  let firedLongPress = false;

  function clear() {
    if (timer) {
      clearTimeout(timer);
      timer = null;
    }
  }

  function onPointerDown(e) {
    if (e.pointerType === "mouse" && e.button !== 0) return;
    startX = e.clientX;
    startY = e.clientY;
    firedLongPress = false;
    clear();
    timer = setTimeout(() => {
      firedLongPress = true;
      onLongPress(e);
    }, thresholdMs);
  }

  function onPointerMove(e) {
    if (!timer) return;
    if (Math.hypot(e.clientX - startX, e.clientY - startY) > moveTolerancePx) clear();
  }

  function onPointerUpOrCancel() {
    clear();
  }

  function onClickCapture(e) {
    if (firedLongPress) {
      e.preventDefault();
      e.stopImmediatePropagation();
      firedLongPress = false;
    }
  }

  function onContextMenu(e) {
    e.preventDefault();
  }

  el.addEventListener("pointerdown", onPointerDown);
  el.addEventListener("pointermove", onPointerMove);
  el.addEventListener("pointerup", onPointerUpOrCancel);
  el.addEventListener("pointercancel", onPointerUpOrCancel);
  el.addEventListener("click", onClickCapture, true);
  el.addEventListener("contextmenu", onContextMenu);
}
```

- `pointermove`で一定距離（既定10px）動いたら長押し判定をキャンセルする（一覧のスクロール操作と区別するため）
- `contextmenu`を止めて、モバイルでの長押し標準メニュー（コピー/共有ポップアップ等）と衝突しないようにする
- 要素の再生成（周辺POI一覧は`renderNearbySection`のたびに`innerHTML=""`で作り直している）に伴うリスナーの再アタッチは、既存の`click`リスナーと同じ扱いでよい（古い要素ごと破棄されるため、明示的なdetachは不要）。そのため`attachLongPress`にdetach関数は用意しない

### `public/js/views/result.js`

- `copyItem(item, { forceLatLon = false } = {})`に変更
  - `forceLatLon`が`true`のとき、`formatCopyText`（アプリ全体設定）を使わず`${item.lat.toFixed(6)}, ${item.lon.toFixed(6)}`を直接コピーする
  - トースト文言を`forceLatLon`のとき「緯度経度をコピーしました」、それ以外は従来通り「コピーしました」にする
- `import { attachLongPress } from "../long-press.js";`を追加
- `copyOpenButton`（目的地の「ナビ用情報」ボタン）に`attachLongPress`を追加。`onLongPress`で`copyItem(picked, { forceLatLon: true })`を呼ぶ
- `renderNearbySection`内、目的地行（`destBtn`）と各POI行（`item`）の生成箇所それぞれに`attachLongPress`を追加。`onLongPress`でその行が指す対象（`picked`または`poi`）を`copyItem(..., { forceLatLon: true })`で強制コピーする（現在の選択状態・フォーカス状態に関わらず、長押しした行を対象にする）

### `public/styles.css`

`.nearby-item`と`#copy-open-button`に、モバイルでの長押し時のテキスト選択・拡大鏡・標準コンテキストメニューを避けるためのスタイルを追加する。

```css
-webkit-touch-callout: none;
-webkit-user-select: none;
user-select: none;
```

## リスク・注意点

- Pointer Eventsは主要モバイルブラウザ（iOS Safari, Chrome）・PCブラウザで広く対応済みだが、実機（iPhone Chrome、要件上の主要想定端末）での長押し挙動は必ず目視確認する
- 長押し中にページスクロールが始まってしまう挙動（特にPOI一覧が縦スクロールする場合）が気になる場合は、CSS `touch-action`の調整を追加で検討する余地がある（今回はまず`pointermove`によるキャンセルのみで様子を見る）

## 検証

- `node --check`で新規・変更JSファイルの構文エラーがないこと
- `npm run typecheck`がエラーなしで通ること
- 実ブラウザで、通常タップのデグレがないこと、長押しでの強制コピーと専用トーストが3箇所すべてで動作すること、スクロール操作で誤発火しないことを確認する
- 本番デプロイ後、軽く疎通確認する

### 4. 実ブラウザ（Playwright）での確認

スクリプト: `test-long-press.js`（スクラッチパッド配下）。2部構成で検証した。

**Part A: `long-press.js`単体挙動（ネットワーク不要）**

| ケース | 結果 |
|---|---|
| 1秒以上の長押し | `onLongPress`が1回発火、直後の`click`は抑止される（`longPressCount:1, clickCount:0`） |
| 短いタップ（50ms） | `onLongPress`は発火せず、`click`が通常通り発火する（`longPressCount:0, clickCount:1`） |
| 長押し中に大きく動く（スクロール相当） | `onLongPress`はキャンセルされ、`click`は通常通り発火する（`longPressCount:0, clickCount:1`） |

いずれも期待通り。

**Part B: 実アプリでの検索→展開→長押しコピー確認**

東京駅周辺（35.681, 139.767）でGeolocationを許可し、実際に検索・周辺情報展開まで行った上で、`page.mouse.down()`→1.1秒待機→`page.mouse.up()`で長押しを再現した。

- 目的地の「ナビ用情報」ボタンを長押し → トースト「緯度経度をコピーしました」、クリップボード内容は緯度経度のみ（`35.650713, 139.634034`）
- 展開一覧内の目的地行を長押し → 同上（同じ緯度経度）
- 周辺POI行を単発タップ → 選択状態（`active`クラス付与）になるのみでコピーされない（デグレなし）
- 同じPOI行を長押し → トースト「緯度経度をコピーしました」、クリップボードは緯度経度のみ（`35.650913, 139.634827`）
- 同じPOI行を通常のタップ→再タップでコピー（回帰確認） → トースト「コピーしました」、クリップボードは緯度経度＋名称「まいばすけっと」（アプリ全体設定通り）
- コンソールエラー: なし

途中、探索範囲50km（帯75km）でのOverpassクエリがサーバー側でタイムアウトする事象（`remark: "runtime error: Query timed out..."`、HTTP自体は200/502が混在）に遭遇したが、`curl`で同一クエリを直接Overpassに投げて再現・原因切り分けを行い、今回のコード変更とは無関係（東京都心部での大規模クエリがOverpass側で重いことによる、既知の特性）と判断した。テストは探索範囲を10kmに変更することで正常に完了させた。この事象自体への対応（クエリの軽量化等）は本計画のスコープ外であり、別途必要であれば改めて検討する。
