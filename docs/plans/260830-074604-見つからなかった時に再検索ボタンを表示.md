# 目的地が見つからなかった時・エラー時に、その場で再検索できるようにする

## Context

実機確認で、「条件に合う目的地が見つかりませんでした。条件を変えてお試しください。」が表示された際、下部シート（再抽選ボタンを含む）ごと非表示になっており、その場で再検索する手段がないという指摘があった。「戻る」を押して条件設定画面に戻り、（条件を変えずに）もう一度「目的地をさがす」を押せば同じことができるため、わざわざ画面遷移を強制する意味がなく、動線として分かりにくい。

同じ理由で、検索エラー時（`state.searchError`、Overpass混雑等）も同様に下部シートごと非表示にしており、同じ問題を抱えている。

## 決定事項

- 「見つからなかった」「エラー」のどちらの状態でも、ステータス表示のその場に「↻ もう一度探す」ボタンを表示し、条件設定画面に戻らずに再検索できるようにする
- 再検索は既存の再抽選と同じ仕組み（`performSearch(store, { isReroll: true })`）を使う。交差点カテゴリは仮地点を毎回引き直す仕様に修正済みのため、再検索で別の結果が出る可能性がある。他カテゴリはキャッシュが変わらない限り同じ結果になりうるが、それ自体は正直な結果であり問題ない
- メッセージ文言はそのまま維持する（「条件を変えてお試しください」という案内と、その場で再検索できるボタンは矛盾しない。変えずに試すか、条件設定画面で変えるかは利用者の判断に委ねる）

## 技術設計

### `public/index.html`

`#result-status`を`<p>`から、メッセージ用の`<p>`とボタンを内包する構造に変更する。

```html
<div id="result-status" class="result-status" hidden>
  <p id="result-status-text"></p>
  <button type="button" id="retry-button" class="primary-button" hidden>↻ もう一度探す</button>
</div>
```

### `public/js/views/result.js`

- `statusTextEl`（`#result-status-text`）・`retryButton`（`#retry-button`）を取得
- `retryButton`のクリックで`performSearch(store, { isReroll: true })`
- `render()`内、`state.searching`のときは`retryButton.hidden = true`のまま、`state.searchError`・`!state.picked`のときは`retryButton.hidden = false`にする

### `public/styles.css`

`.result-status .primary-button`に`margin-top`を追加する。
