# Phase 3: 周辺情報表示（周辺情報展開画面）実装計画

## Context

Phase 1・2で「店」タイプ検索の一気通貫フロー（条件設定→検索→地図表示→再抽選→ナビ用情報コピー）と、本番デプロイ・Overpassのブラウザ直接fetch方式が確立した（docs/roadmap.md）。探索範囲の帯検索修正（docs/decisions/260829-search-radius-band.md）も完了した。要件7「周辺情報表示」は未実装で、docs/mockups/result-expanded.pngに示される「結果画面の下部シートを引き上げると、目的地本体＋周辺POI一覧が表示され、一覧タップで地図上の該当地点にフォーカスできる」という機能を実装する。

**この機能は探索範囲の帯検索とは独立している。** 周辺POI検索は目的地決定後の固定半径（500m）の円内検索であり、帯の仕組みは適用しない（docs/decisions/260829-search-radius-band.md に明記済み）。

## 要件で明記されていない解釈（実装前に確認済み・以下の内容で進める）

1. 周辺POI一覧には高速道路100m除外フィルタを適用しない（この制約は「目的地候補」向けであり、周辺情報は表示専用の付随情報のため対象外と解釈）
2. 神社・寺院等は`amenity=place_of_worship`のみで判定する（宗派タグ`religion=*`までは見ない）
3. 一覧の並び順は目的地からの距離昇順（近い順）とする（モックアップの数値表示順は昇順になっておらず、厳密な仕様ではないと判断）
4. 周辺POI検索半径は固定500m、表示件数は上位5件（モックアップの「近くのスポット（5件）」に合わせる）。両方とも定数化し調整可能にする
5. 目的地自体は周辺POI一覧から除外する（同一Overpass要素が重複しうるため`excludeId`で除外）

## 全体アーキテクチャ

Overpassクライアント直接fetchの3段階パターン（docs/decisions/260829-overpass-client-side-fetch.md）を、新しい「周辺POI検索」にもそのまま踏襲する。目的地検索（`/api/destinations/*`）とは別に`/api/nearby/*`として新設する（キャッシュキー設計・検索半径が別物のため）。

```
1. ブラウザ → Worker（POST /api/nearby/prepare）: 目的地の座標＋excludeIdを送る
2. キャッシュあり → Workerが周辺POI一覧を返して終了（Overpassにはアクセスしない）
2'. キャッシュなし → WorkerがOverpass用クエリ文字列を返す
3. ブラウザ → Overpass API（直接、既存のfetchOverpassDirectを再利用）
4. ブラウザ → Worker（POST /api/nearby/process）: Overpassの生応答＋座標＋excludeIdを渡し、最終結果を受け取る
```

## バックエンド設計

### `src/types.ts`（拡張）
`PoiKind`（"parking"|"shrine_temple"|"vending_machine"|"fuel"|"toilets"|"food_rest"|"shop"|"other"）、`PoiItem`、`RankedPoiItem`（`PoiItem`+`distanceM`）、`NearbyPrepareRequestBody`、`NearbyResponseBody`、`NearbyPrepareResponseBody`（done/need_fetchユニオン、既存`PrepareResponseBody`と同型）、`NearbyProcessRequestBody`（lat/lonを含む点が既存`ProcessRequestBody`と異なる＝距離ランキングの原点座標が必要なため）を追加。

### `src/lib/candidate.ts`（軽微修正）
`buildAddress`を`export`し、`poi.ts`から再利用する（重複実装を避ける）。

### `src/lib/poi.ts`（新規）
`classifyPoiKind(tags)`（amenity/shopタグからPoiKindを判定）、`toPoiItems(elements)`（Overpass要素→PoiItem変換。`candidate.ts`の`toCandidates`と対になる役割）。

### `src/lib/nearby.ts`（新規）
`NEARBY_POI_RADIUS_M = 500`, `NEARBY_POI_LIMIT = 5`定数。`buildNearbyQuery(lat, lon)`（parking/place_of_worship/vending_machine/fuel/toilets/食事系amenity＋shopタグを対象、高速道路除外文は含めない単一クエリ）。`rankNearbyPois(pois, originLat, originLon, excludeId, limit)`（excludeId除外→距離計算→距離昇順ソート→上位N件）。

### `src/lib/cache.ts`（拡張）
`buildNearbyCacheKey(lat, lon)`（`bucketCoordinate`を500m相当の粒度で流用、`poi:v1:{bucketLat}:{bucketLon}`）、`getCachedPois`/`putCachedPois`（既存`getCachedCandidates`等と同パターン、TTL24時間）。キャッシュには除外・ランキング前の生POIリストを保存し、`excludeId`除外とランキングはリクエストごとに行う（既存の候補キャッシュと同じ設計思想）。

### `src/routes/nearby.ts`（新規）
`destinations.ts`の`prepare`/`process`と同型。`/prepare`はキャッシュ確認→ヒットならランキング済み結果、ミスならOverpassクエリを返す。`/process`は生応答を`parseOverpassResponse`で検証→`toPoiItems`→キャッシュ保存→ランキングして返す。

### `src/index.ts`（拡張）
`app.route("/api/nearby", nearby)`を追加。

## フロントエンド設計

### `public/js/app.js`（拡張）
store初期状態に`sheetExpanded`, `nearbyPois`, `nearbyLoading`, `nearbyError`, `nearbyFetchedForId`（どのpicked.idに対して取得済みか、再取得要否の判定に使う）, `focusedPoiId`を追加。**`view`状態は増やさない**（画面遷移なしの要件を満たす。同じ結果画面内でのシート展開として実装）。

### `public/js/api.js`（拡張）
`prepareNearby`, `processNearby`を追加。既存の`fetchOverpassDirect`はそのまま再利用。

### `public/js/nearby.js`（新規）
`loadNearbyPois(store)`: `nearbyFetchedForId === picked.id`なら再取得しない。prepare→(必要なら直接fetch)→processのオーケストレーション。`search.js`と対になる役割。

### `public/js/components/map.js`（拡張）
`showNearbyPois(pois)`（POI群の点マーカー描画）、`focusPoi(lat, lon)`（緑の輪っかマーカー＋flyTo）、`clearNearbyPoiMarkers`/`clearFocusRing`を追加。既存の`showCandidate`（目的地ピン＋破線ルート）はそのまま「目的地にフォーカスし直す」動作として温存。

### `public/index.html` / `public/styles.css`（拡張）
`#result-sheet`内を折り畳み時ブロック（既存内容＋「⌃ 周辺のスポットを見る」トグル追加）と展開時ブロック（「⌄ 地図に戻る」、目的地行、POI一覧）に分け、`hidden`属性で出し分ける。POI一覧・目的地行はJSで動的に組み立てる（空divを用意）。展開時のシートは画面をほぼ覆うレイアウトにする。

### `public/js/views/result.js`（拡張、最も複雑な変更）
- シート展開トグル、収縮ボタン、目的地行/POI行タップのイベントハンドラ追加
- `render(state)`内でのPOI一覧再構築（アイコン・名称・距離ラベル・`.active`ハイライト）
- **地図フォーカスの重複適用防止**: `render`は状態変化のたびに呼ばれるため、`showCandidate`/`focusPoi`を無条件に毎回呼ぶと`map.flyTo`が余計に再発火しカメラがガタつく。モジュールスコープに`lastAppliedFocus`を持ち、直前と対象が変わった時だけ地図操作を行う`applyMapFocus(state)`を新設する（Phase 1で実際に踏んだ「地図初期化タイミング」の罠と同種の問題を設計段階で回避する）
- 同様に`showNearbyPois`も`nearbyFetchedForId`が変わった時だけ呼ぶ

### `public/js/search.js`（軽微修正）
`performSearch`の状態リセット処理に、シート展開・POI関連state（`sheetExpanded`, `nearbyPois`, `nearbyFetchedForId`, `focusedPoiId`, `nearbyError`）のリセットを追加（再抽選・条件画面に戻った際に古いPOIリストが残らないようにする）。

## 変化一覧

### 実機で発覚: 展開時のシートが地図を完全に覆ってしまう不具合

`public/styles.css`の`.sheet.expanded`を`position: fixed; inset: 0;`（画面全体を覆う）として実装していたため、シート展開中は地図が完全に隠れ、POIタップ時の地図フォーカス移動（`focusPoi`）が実行されていても利用者からは見えない状態になっていた。要件7「地図確認の流れの中で利用できること」の趣旨に反する実装だった。Playwrightでの事前E2Eでは地図の可視性を検証項目に含めていなかったため、この時点まで発見できなかった。

**対応**: `.sheet.expanded`を`position: fixed`をやめ、`max-height: 65vh; overflow-y: auto;`に変更し、地図（`#map`, 60vh）を隠さずシートが下に展開される形に修正。再デプロイし、スクリーンショットで地図が見えたまま展開されることを確認した。

この修正の結果、実機で「地図連動は想定通り」との確認が得られた。ただし「周辺POIの情報をコピーできない」という新たな指摘があり、別途 `docs/plans/260829-121720-コピー項目設定と周辺POIコピー.md` として計画・実装した。
