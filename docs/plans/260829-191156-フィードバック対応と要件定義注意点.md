# フィードバック対応（コピー空防止・探索範囲帯の中抜け解消・UI余白）

## Context

本番環境を実際に操作する中で3件の改善点が見つかった。いずれも要件検討時の見落としであり、Phase 4着手前に対応する。あわせて、同種の見落としを将来の要件定義で防ぐための注意点をCLAUDE.mdと一般教訓（メモリ）に記録する。

## 対応する3件

### A. コピー結果が空になりうる問題

現在の`formatCopyText`（`public/js/copy-preference.js`）は、設定で選んだ項目（緯度経度／名称／住所）がその候補にたまたま存在しない場合（例: 名称のみ選択なのに名称不明）、コピー結果が空文字列になる。ナビアプリに渡すという本アプリの目的を果たせないため、バグとして扱う。

**方針**: 選択した項目をすべて適用した結果が空になる場合は、必ず緯度経度をコピーする（緯度経度はどの候補にも必ず存在するため、最終フォールバックとして適切）。名称不明の候補を除外する対応は取らない（個人・身内利用アプリとして、正体不明の地点も候補になりうる面白さを維持する）。

### B. 探索範囲の帯に中抜けがある問題

現在の帯（`computeDistanceBand`、`src/lib/geo.ts`と`public/js/geo.js`に同一ロジックを重複実装）は、指定距離ごとに独立してマージン（指定距離の10%と固定5kmの大きい方）を適用しており、10km→[5,15]、30km→[25,35]、50km→[45,55]、100km→[90,110]と、選択肢の間（15〜25km、35〜45km、55〜90km）が一切検索できない「中抜け」が生じていた。再抽選機能がある以上、意図的に中抜けを残すのは利用者への押し付けになる、という判断で解消する。

**方針**: 隣り合う選択肢どうしの境界を、2つの数値の中間値にする。両端（最小・最大の選択肢）だけ、これまで通りのマージン計算式を使う。

| 指定距離 | 新しい帯 |
|---|---|
| 10km | 5〜20km |
| 30km | 20〜40km |
| 50km | 40〜75km |
| 100km | 75〜110km |

これは探索範囲の絞り込みロジックの変更にあたるため、docs/decisions/260829-cache-key-versioning.mdの原則に従い、**KVキャッシュキーのバージョンを`ov:v2`→`ov:v3`に上げる**。

### C. コピー設定リンクの余白不足

`public/styles.css`で、`.link-button`に`margin-bottom`が、`.card`に`margin-top`が設定されておらず、条件設定画面の「コピーする情報を選ぶ」リンクと現在地カードが接触して見える。`.link-button`に`margin-bottom`を追加する。

## 要件定義時の一般的な注意点（記録する内容）

今回の A・B は、個別に見れば別々の見落としだが、共通する一般原則がある: **選択可能な項目の組み合わせ（設定の掛け合わせ、離散的な選択肢を連続範囲に変換する設計）を導入する際は、あらゆる組み合わせ・境界を実際に机上または実地で検証し、(1)結果が空・無意味になる組み合わせがないか、(2)選択肢全体でカバーすべき範囲に意図しない抜けがないか、を確認する必要がある。個々の選択肢を単体で見ているだけでは気づけない**。

この注意点を、CLAUDE.mdの「作業の進め方」に追記し、プロジェクトを超えて使える一般教訓としてメモリにも記録する。

## 技術設計

### `src/lib/geo.ts` / `public/js/geo.js`（両方に同一ロジックを反映）

```ts
const RADIUS_STEPS = [10, 30, 50, 100]; // 選択肢chip値。中抜けのない帯を作るため隣接値を使う

export function computeDistanceBand(radiusKm: number) {
  const idx = RADIUS_STEPS.indexOf(radiusKm);
  const marginKm = Math.max(radiusKm * RADIUS_BAND_TOLERANCE, RADIUS_BAND_MIN_MARGIN_KM);
  const innerKm = idx <= 0 ? radiusKm - marginKm : (RADIUS_STEPS[idx - 1] + radiusKm) / 2;
  const outerKm =
    idx === -1 || idx === RADIUS_STEPS.length - 1
      ? radiusKm + marginKm
      : (radiusKm + RADIUS_STEPS[idx + 1]) / 2;
  return { innerKm, outerKm, marginKm };
}
```
`idx === -1`（未知の値が渡された場合）は両端と同じ扱い（対称マージン）にフォールバックし、関数として壊れないようにする。

### `src/lib/cache.ts`
`buildCacheKey`のプレフィックスを`ov:v2`→`ov:v3`に変更。コメントで理由（帯の中抜け解消による絞り込みロジック変更）を明記。

### `public/js/copy-preference.js`
`formatCopyText`の末尾に、`lines.length === 0`なら緯度経度を追加するフォールバックを追加。

### `public/styles.css`
`.link-button`に`margin-bottom: 16px;`程度を追加。
