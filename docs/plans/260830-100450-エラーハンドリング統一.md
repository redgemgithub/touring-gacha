# エラーハンドリングの統一（コピー失敗・地図読み込み失敗・検索エラーの一貫性）

## Context

Phase 5の残項目としてエラーハンドリングを洗い出したところ、以下3点のギャップが見つかった。
1. コピー失敗時（clipboard API不在・書き込み失敗）に何もフィードバックがなく、利用者からはタップが効いていないのか失敗したのか区別がつかない
2. MapTilerの設定取得（`/api/config`）に失敗すると地図が読み込めないまま無言で固まる
3. 目的地検索と周辺情報検索でエラーメッセージの文言・粒度がバラバラだった

ユーザーの方針指示: 技術的に競合しないので3件まとめて対応する。「エラーが起きたら簡単なメッセージで通知する」「同じ系統のエラーには同じメッセージ」「利用者は非開発者。いま使えないとわかればそれでよく、技術的詳細は不要」。

## 実行の経緯（本来の計画プロセスからの逸脱）

この対応もユーザーからの方針指示を受けてそのまま実装に着手し、事前の計画ファイル作成・承認を経ていない。本ファイルは実行後の事後記録として作成した。[[260830-094238-現在地アイコンの状態色分け]]と同種の逸脱。

## 実施内容

- `public/js/api.js`: `describeApiError(err)`を追加。`err.status===503`→「混み合っています。しばらくしてからお試しください。」、それ以外→「取得できませんでした。もう一度お試しください。」の2系統に統一
- `public/js/search.js` / `public/js/nearby.js`: それぞれのcatch節が個別に持っていた文言分岐を`describeApiError(err)`呼び出しに置き換え、両機能で同じエラー系統に同じ文言が出るようにした
- `public/js/views/result.js`の`copyItem`: clipboard API不在・書き込み失敗のいずれでも「コピーできませんでした」トーストを必ず表示するようにした（従来は無言で失敗）
- `public/js/app.js`: store状態に`mapTilerApiKeyError`を追加。`getConfig()`失敗時に`true`をセット
- `public/index.html`: `#map`内に`#map-error`（「地図を読み込めませんでした」、初期`hidden`）を追加
- `public/styles.css`: `.map-error`（`#map`に対して`position:absolute; inset:0`で中央寄せ表示）を追加
- `result.js`の`render()`で`mapErrorEl.hidden = !state.mapTilerApiKeyError`を反映

## 確認

- `node --check`（変更した5ファイル全て）・`npm run typecheck`：エラーなし
- Playwright（`wrangler dev`起動、`page.route`によるモックで各エラー経路を再現）
  - clipboard書き込み失敗 → トースト「コピーできませんでした」を確認
  - `/api/config`失敗 → `#map-error`が表示され文言も正しいことを確認（スクリーンショット確認）
  - Overpass 429（目的地検索）→「混み合っています。しばらくしてからお試しください。」を確認
  - Overpass 500（目的地検索、非503系だがOverpass 5xxとして扱われるケース）・Overpass 429（周辺情報検索）→ 両方とも同じ「混み合っています…」文言で一致することを確認（`fetchOverpassDirect`が429と5xxを既存ロジックでどちらも`err.status=503`にマッピングしているため、この2つが同じ文言になるのは意図通り）
  - Overpassが200だが`remark`付き（内部タイムアウト相当、当方Workers側で`overpass_error`として502を返すケース）→「取得できませんでした。もう一度お試しください。」（汎用メッセージ）になることを確認し、503系（混雑）と502系（当方側の処理エラー）が正しく別文言に分かれることを確認
