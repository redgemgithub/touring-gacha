# コピー項目設定（アプリ共通）と周辺POIのコピー対応

## Context

Phase 3の実機確認で、周辺情報展開画面で周辺POIを選択（フォーカス）できても、その情報をコピーできず、ナビアプリでの検索に使えないという指摘があった。対応方法を協議した結果、以下の方針で合意した。これは実装の細部にとどまらず、コピーの仕組みそのものの仕様変更にあたるため、決定記録を作成した（[docs/decisions/260829-copy-preference.md](../decisions/260829-copy-preference.md)）。

- コピーする項目（緯度経度／名称／住所）の選択は、利用者ごとに使うナビアプリがほぼ固定されているという前提のもと、**コピーの都度ではなくアプリ全体で1回設定する**（localStorageに保存）
- 既存のコピーモーダルを「今すぐコピーするボタン集」から「次回以降のコピーに何を含めるかを選ぶ、チェックボックス付きの設定画面」に役割変更する
- 設定の入り口は条件設定画面の上部に置く
- 実際のコピー操作はモーダルを介さず直接行う。目的地は既存の「ナビ用情報」ボタンをタップした瞬間にコピー、周辺POIはタップで選択→もう一度タップでコピー。どちらも「コピーしました」の短い表示を出す

## DoD（完了条件）

1. 条件設定画面から「コピーする情報を選ぶ」的なリンク/ボタンでモーダルを開くと、緯度経度／名称／住所のチェックボックスが表示され、変更が即座にlocalStorageへ保存される
2. 全項目のチェックを外そうとした場合は、最低1項目のチェックを維持する（空コピーを防ぐ）
3. 目的地の「ナビ用情報」ボタンをタップすると、モーダルを開かず、設定に従った内容が即座にクリップボードにコピーされ、「コピーしました」が短時間表示される
4. 周辺情報展開画面のPOI行をタップすると選択（地図フォーカス、既存動作）、選択中の行をもう一度タップするとコピー＆「コピーしました」表示
5. 周辺情報展開画面の目的地行も同様（選択中に再タップでコピー）
6. `npm run typecheck`が通り、実ブラウザで一連の流れを確認できる

## 技術設計

### `public/js/copy-preference.js`（新規）
- `getCopyPreference()`: localStorageから読み込み、`{ latlon: boolean, name: boolean, address: boolean }`を返す（未保存時は全てtrueがデフォルト）
- `setCopyPreference(pref)`: localStorageへ保存
- `formatCopyText(item, preference = getCopyPreference())`: `item`（Candidate/PoiItem共通、lat/lon/name/addressを持つ）と設定から、改行区切りのコピー用テキストを組み立てる（住所はitem側に値がある場合のみ含める）

### `public/js/toast.js`（新規）
- `showToast(message)`: `#toast`要素に短時間メッセージを表示する（1.5秒程度で自動的に隠す）

### `public/js/views/copy-modal.js`（全面書き換え）
- `initCopyModal()`: 開閉ボタンの配線に加え、3つのチェックボックスの初期状態を`getCopyPreference()`から設定し、変更のたびに`setCopyPreference()`で保存する。全解除を防ぐガードを入れる。条件設定画面の設定リンクのクリックもここで配線する（モーダルの開閉ロジックを1箇所にまとめるため）
- `openCopyModal()`は設定編集用途に変わるため引数なしにする。既存の「コピー実行」役割は`copy-preference.js`の`formatCopyText`＋`navigator.clipboard`を直接呼ぶ形に置き換わり、`result.js`側に移る

### `public/js/views/result.js`（修正）
- 目的地の「ナビ用情報」ボタン: `openCopyModal(picked)`の呼び出しをやめ、`formatCopyText(picked)`→`navigator.clipboard.writeText`→`showToast("コピーしました")`に変更
- 周辺情報展開画面のPOI行・目的地行のクリックハンドラ: 「すでに選択中（focusedPoiIdが一致）」なら上記と同じコピー処理、そうでなければ従来通り選択（フォーカス）のみ

### `public/index.html`
- `#view-condition`の`.app-header`内に設定リンク（例: `<button id="copy-settings-open-button" class="link-button">⚙ コピーする情報を選ぶ</button>`）を追加
- `#copy-modal`の中身を、コピー実行ボタン群からチェックボックス3つ（緯度経度／名称／住所）に置き換える
- `<p id="toast" class="toast" hidden></p>`をbody直下に追加

### `public/styles.css`
- `.link-button`（設定リンクの見た目）、`.checkbox-row`（チェックボックス行）、`.toast`（画面下部などに短時間表示する小さな通知）のスタイルを追加

## リスク・注意点

- localStorageが使えない環境（プライベートブラウジング等）でも致命的にならないよう、読み書きは例外処理で保護する
- 全チェック解除を防ぐガードの実装を忘れないこと（空コピー防止）
- 目的地の「ナビ用情報」ボタンの挙動が変わる（モーダルを開かなくなる）ため、既存の動作に慣れている場合の体験変化として認識しておく

## 実行結果

計画通りステップ1〜10を実施した。

- ステップ1〜6（`copy-preference.js`/`toast.js`新規、`index.html`/`styles.css`修正、`copy-modal.js`全面書き換え、`result.js`修正） → 完了
- ステップ7（typecheck・構文チェック） → エラーなし
- ステップ8（実ブラウザE2E、Playwright）:
  - 設定モーダルのデフォルト値（緯度経度/名称/住所すべてtrue）を確認
  - 名称・住所のチェックを外し、最後の1つ（緯度経度）を外そうとしたところ、ガードにより外れないことを確認（`.uncheck()`がPlaywright側で「状態が変化しなかった」というエラーを出したこと自体が、ガードが正しく機能している証拠だった）
  - localStorageへの保存内容（`{"latlon":true,"name":false,"address":false}`）を確認
  - ページ再読込後も設定が保持されることを確認
  - 目的地の「ナビ用情報」ボタンをタップ→モーダルを開かず即座にクリップボードへコピーされ（設定通り緯度経度のみ）、「コピーしました」表示が出ることを確認
  - 周辺POI一覧で1回目タップ（選択）→2回目タップ（コピー）で、そのPOIの緯度経度がクリップボードにコピーされることを確認
  - コンソールエラーなし
  - **この過程でトースト表示の不具合を発見**（下記「変化一覧」参照）
- ステップ9（本番デプロイ・実機確認） → デプロイ成功、`/api/health`確認済み。今回はコピー機能のみでOverpassへの新規リクエストは発生しないため、実機での追加確認は行っていない
- ステップ10（ドキュメント更新） → `docs/requirements.md`6・7節、`CLAUDE.md`守るべきドメインルール、`docs/feature-map.md`、`docs/roadmap.md`を本ファイル完成までに更新済み

## 変化一覧

### トースト表示が「この場所に決める」ボタンと重なる不具合

`.toast`を画面下部（`bottom: 24px`）に固定表示する実装にしたところ、結果画面の下部シートのボタン群と位置が重なり、「この場所に決めるコピーしました」のように文字が重なって表示された。Playwrightのスクリーンショットで発見した。

**対応**: `.toast`の位置を画面下部から上部（`top: 16px`）に変更し、影（box-shadow）を付けて視認性を確保した。再確認のスクリーンショットで、他要素と重ならず表示されることを確認した。
